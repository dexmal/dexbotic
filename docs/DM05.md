# DM05 Tutorial

DM0.5 is Dexmal's open-world VLA: a 4B VLM plus a 680M Action Expert that emits continuous actions with Flow Matching. It is larger than DM0, and history, embodied reasoning, action supervision, and data quality are stronger, so the model can track task progress, follow open instructions, and stay stable under camera change and human interference.

Main gains (pretrained):

- Zero-shot: follow language in unseen open scenes (8 primitives, 7 condition types).
- Fine-tune: a stronger base gives cheaper, better specialists.
- Long memory: history up to 60 seconds.
- Robust actions: lighting, camera motion, human perturbation.
- Multi-embodiment: multi-robot pretrain, then transfer.

This repo implements **Gemma3 VLM + Gemma3 Action Expert**.

![DM0.5 model overview](../resources/dm05_model_overview.png)

More narrative and official eval videos: [DM0.5 blog](https://www.dexmal.com/blog/dm0.5).

## Pretrained Model

Download the Hugging Face base weights to `checkpoints/DM05`. Playground training defaults resolve to that path.

| Model | Description | Input Images | Action Dim | Backbone | Link |
| - | - | - | - | - | - |
| DM05 | Base Gemma3 VLM + Flow Matching Action Expert | set by the recipe (LIBERO: 2; RoboTwin2: 3) | padded to 32D (LIBERO valid dim 7; RoboTwin2 valid dim 14) | 4B VLM | [🤗 Hugging Face](https://huggingface.co/Dexmal/DM05) |

## Installation and Environment Setup

The DM05 image is `dexmal/dexbotic:dm05`. Clone the repo on the host, mount it into the container, then install the mounted source.

```bash
git clone https://github.com/Dexmal/dexbotic.git

docker run -it --rm --gpus all --network host \
  -v /path/to/dexbotic:/dexbotic \
  dexmal/dexbotic:dm05 \
  bash

cd /dexbotic
conda activate dexbotic
pip install -e .
```

Local conda install if you are not using Docker:

```bash
git clone https://github.com/Dexmal/dexbotic.git
conda create -n dexbotic python=3.10 -y
conda activate dexbotic

pip install torch torchvision \
  --index-url https://download.pytorch.org/whl/cu128

pip install ninja packaging
MAX_JOBS=2 pip install flash-attn --no-build-isolation

cd dexbotic
pip install -e .
pip install transformers==5.3.0
```

The default train recipes below need 8 GPUs (H20 / A100 / H100 for full SFT; 4090 works for LoRA). One GPU is enough for inference. FSDP2 notes: [FSDP2.md](FSDP2.md).

## Training

All provided-data recipes start from `./checkpoints/DM05` and use the same
DM0.5 model, trainer, checkpoint format, and normalization lifecycle. Select a
benchmark entrypoint for the data and action contract; benchmark-specific code
is an adapter around the shared pipeline, not a separate trainer.

### Prepare Provided Data

#### LIBERO

The LIBERO recipes train on `libero_pi0_all` from
[Dexmal/libero](https://huggingface.co/datasets/Dexmal/libero). After download,
the split should sit under `data/libero`.

```bash
hf download Dexmal/libero \
  --repo-type dataset \
  --local-dir data/.hf_downloads/libero

mkdir -p data/libero
cp -a data/.hf_downloads/libero/libero_pi0_all data/libero/

```

If the download is archives instead of a folder, extract into `data/libero` so
those two paths exist. Dataset catalog:
[Data.md](Data.md#using-provided-data).

[Dexmal/robotwin2-full](https://huggingface.co/datasets/Dexmal/robotwin2-full).
After download, the splits should sit under `data/robotwin2.0`.


All three recipes start from `./checkpoints/DM05` and use
`diffusion_steps=10`, pad-to-square then `448×448`, `bf16`, and
`save_hf_sidecar=True`.

#### LIBERO

```bash
# full SFT
torchrun --nproc_per_node=8 playground/benchmarks/libero/libero_dm05.py --task train --train-backend fsdp2

# LoRA
pip install "peft>=0.13.0"
export NCCL_P2P_DISABLE=1   # multi-GPU 4090 only

torchrun --nproc_per_node=8 playground/benchmarks/libero/libero_dm05_lora.py --task train --train-backend ddp
```

LoRA writes `adapter_model.safetensors` + `adapter_config.json` and
`checkpoint-{step}-hf`. Infer merges the adapter; continuing from an adapter
keeps `PeftModel`. More LoRA recipe notes:
[LiberoLora.md](LiberoLora.md#dm05-lora-recipe).

#### RoboTwin2

Omitting `--dataset-name` selects all 100 registered clean/randomized datasets.

```bash
torchrun --nproc_per_node=8 \
  playground/benchmarks/robotwin2/robotwin2_dm05.py \
  --task train \
  --train-backend fsdp2
```

Each frame must contain a finite 14-D `state`, a `prompt`, and `images_1/2/3`
in Head / Left wrist / Right wrist order. Episodes shorter than 30 frames are
excluded. The RoboTwin2 adapter replaces stored `action` with the next 50
absolute states beginning at `state[t+1]`, repeats the final state for tail
padding, and excludes the last frame as an input. LIBERO uses its stored action
trajectory directly; both paths then use the same DM0.5 model and trainer.

RoboTwin2 `norm_stats.json` contains `state` and `action`, optionally under
`norm_stats`, each with 22 finite `min`/`max` values and `max >= min`. The first
14 dimensions are physical and the remaining 8 have zero bounds. Tensors are
then padded to 32 dimensions, and only the first 14 action dimensions
contribute to the loss.

Tokens are padded to the longest sample in the batch, while `max_length`
limits tokenization length.

### Normalization Statistics

Both recipes require `norm_stats.json`. If it is missing at training start,
rank 0 computes it and the other ranks wait. Inference never computes missing
statistics; keep the file with the trained model.

For LIBERO:

```bash
python playground/benchmarks/libero/libero_dm05.py --task compute_norm_stats
```

For RoboTwin2:

```bash
python playground/benchmarks/robotwin2/robotwin2_dm05.py --task compute_norm_stats
```

## Inference

`DM05InferenceConfig.backend` selects one of two inference paths:

| Backend | Vision path | Prefix and action path | History frames |
| --- | --- | --- | --- |
| `default` | PyTorch | Dynamic KV-cache inference | Supported |
| `fast` | TensorRT | DM05 Triton kernels with fixed prefix buckets | Supported; requests containing history bypass CUDA Graph capture |

Both backends expose the same HTTP service on `0.0.0.0:7891` by default,
including `/health`, `/v1/capabilities`, `/v1/infer`, `/v1/reset`, and the
legacy `/process_frame` route. The backend only changes how the model executes;
switching between `default` and `fast` does not change a benchmark's request
format.

The benchmark entrypoint selects only the request/prompt/action adapter. It does
not select a different inference engine:

| Contract | LIBERO | RoboTwin2 |
| --- | --- | --- |
| Entrypoint | `playground/benchmarks/libero/libero_dm05.py` | `playground/benchmarks/robotwin2/robotwin2_dm05.py` |
| RGB images | 2: `agentview`, `wrist` | 3: Head, Left wrist, Right wrist |
| State | Optional; zero-padded by the generic policy | Required finite 14-D Aloha state |
| Returned action | `10 x 7` | `50 x 14` |

RoboTwin2 keeps a dedicated adapter because it must reproduce the three-view,
state-conditioned prompt used during SFT and validate the evaluator's 14-D
state and `50 x 14` output contract. Model loading, normalization, HTTP routes,
history support, and the `default`/`fast` execution paths remain shared.

### Start an inference service

Run from the repository root. Replace the checkpoint paths with a complete
Hugging Face checkpoint directory or `checkpoint-*-hf` directory containing
`norm_stats.json`.

The default backend uses PyTorch and requires no optional plugin:

```bash
# LIBERO
CUDA_VISIBLE_DEVICES=0 python playground/benchmarks/libero/libero_dm05.py \
  --task inference \
  --backend default \
  --port 7891 \
  --model-name-or-path /path/to/libero-dm05-checkpoint

# RoboTwin2
CUDA_VISIBLE_DEVICES=0 python playground/benchmarks/robotwin2/robotwin2_dm05.py \
  --task inference \
  --backend default \
  --port 7891 \
  --model-name-or-path /path/to/robotwin2-dm05-checkpoint
```

The fast backend supports batch size 1 and recommends PyTorch >= 2.9.0. Install
the optional plugin, then use the same benchmark entrypoint and request format
with `--backend fast`:

```bash
bash plugins/dm05-fast/install.sh

# Set this to the LIBERO or RoboTwin2 entrypoint above.
ENTRYPOINT=playground/benchmarks/libero/libero_dm05.py
CUDA_VISIBLE_DEVICES=0 python "$ENTRYPOINT" \
  --task inference \
  --backend fast \
  --port 7891 \
  --model-name-or-path /path/to/dm05-checkpoint
```

Fast inference uses BF16 prefix MLPs unless compatible
[optional FP8 artifacts](#optional-fp8-prefix-mlp-optimization) are available.
For BF16, the vision engine is built at startup if missing. Use
`--no-build-engine-if-missing` to require an existing engine, and use a distinct
`--vision-trt-engine-path` for each checkpoint and image-slot configuration,
including
[history-enabled inference](#history-frame-inference).

### Backend configuration reference

Relevant `DM05InferenceConfig` settings:

| Setting | Default | Meaning |
| --- | --- | --- |
| `backend` | `"default"` | Select `default` or `fast` inference |
| `model_max_length` | `None` | Optional preprocessing prefix-length limit |
| `vision_trt_engine_path` | `checkpoints/trt_engines/dm05_vision.engine` | Vision engine for BF16 fast inference, including history |
| `build_engine_if_missing` | `True` | Build the BF16 vision engine at startup if needed |
| `force_rebuild_engine` | `False` | Skip automatic FP8 selection, rebuild the configured vision engine, and use BF16 prefix MLPs |
| `prefix_seq_len_buckets` | `[576, 704, 768, 896, 1024]` | Fixed prefix lengths available to the fast runtime |
| `fast_overflow_policy` | `"fallback"` | Use dynamic BF16 execution or raise an error when the prefix exceeds the largest bucket |
| `fast_prefix_qkv_mode` | `"packed"` | Select packed or separate prefix QKV projection |
| `history_enabled` | `False` | Accept explicit history frames |
| `max_history_images` | `5` | Maximum history frames accepted by the policy |

Without history frames, the first request in each prefix bucket captures a
CUDA Graph; subsequent requests in that bucket replay it. Overflow fallback
uses BF16 prefix MLPs even when FP8 engines are enabled.

#### Optional FP8 prefix MLP optimization

FP8 prefix MLPs are an optional optimization for the `fast` backend. They use
static activation scales from offline calibration and require BF16 model
weights, history disabled, and a GPU/TensorRT installation that supports FP8.

With `--backend fast`, the service automatically loads a compatible vision/FP8
MLP pair from `<checkpoint>/.dexbotic/fast_fp8/prepared.json`. Missing, damaged,
or incompatible artifacts fall back to BF16 fast inference. FP8 engines must
be prepared offline; they are not built at service startup.

First save representative deployment inputs using the same policy preprocessing
as the service. For LIBERO, initialize the policy without starting HTTP:

```python
import torch
from dexbotic.exp.dm05_exp import DM05InferenceConfig

config = DM05InferenceConfig(
    model_name_or_path="/path/to/dm05-checkpoint",
    backend="default",
    chunk_size=10,
)
config._initialize_inference()

keys = ("pixel_values", "input_ids", "attention_mask", "token_type_ids")
samples = []
with torch.inference_mode():
    for observation in representative_observations:
        batch, _ = config.policy.prepare_inputs(observation)
        samples.append({key: batch[key].detach().cpu() for key in keys})
torch.save(samples, "calibration_inputs.pt")
```

`representative_observations` is your collection of real requests: each contains
`prompt`, `image/0` (agentview), and `image/1` (wrist), with RGB images in the
same orientation used by the deployment client. At least two distinct samples
are required; cover the intended tasks and use separate episodes for validation.
Each saved sample may additionally include `diffusion_input_noise` and
`action_mask`.

For RoboTwin2, use `RoboTwin2InferenceConfig` from
`playground.benchmarks.robotwin2.robotwin2_dm05` with its checkpoint and
`chunk_size=50`. Supply three RGB images in `Head`, `Left wrist`, `Right wrist`
order and a 14-dimensional `state`.

Then prepare the vision/FP8 MLP pair offline in the same GPU/CUDA/TensorRT
environment used for serving. For LIBERO:

```bash
CUDA_VISIBLE_DEVICES=0 python -m dexbotic.model.dm05.infer.fast.build_prefix_mlp_trt \
  --checkpoint /path/to/dm05-checkpoint \
  --num-images 2 \
  --chunk-size 10 \
  --calibration-inputs ./calibration_inputs.pt
```

For RoboTwin2, use its checkpoint and calibration inputs with `--num-images 3`
and `--chunk-size 50`. Match the serving chunk size explicitly; if omitted,
preparation uses the checkpoint's saved value. This command builds both the
vision and FP8 MLP engines.

Start the matching service as described in
[Start an inference service](#start-an-inference-service), using `--backend fast`
and the same checkpoint. No additional FP8 flag is needed. Check for the startup log
`Enabled native FP8 prefix MLP with vision engine ...` to confirm selection.

For custom prefix lengths, pass `--prefix-buckets` when building and
`--prefix-seq-len-buckets` when serving. Active serving buckets must fit the
engine's sequence range. See the [backend configuration reference](#backend-configuration-reference)
for defaults and overflow behavior. Rebuild and recalibrate after changing the
checkpoint, preprocessing, camera count, chunk size, or GPU/CUDA/TensorRT
environment, and validate task accuracy and latency before deployment.

### Inference Performance

BF16 fast results:

| GPU | Default latency | Fast latency | Approx. speedup |
| --- | ---: | ---: | ---: |
| RTX 4090 D | 523.7 ms | 103.4 ms | 5.1x |
| H20 | 610.0 ms | 129.1 ms | 4.7x |

Measured with a real DM05 checkpoint, BF16 loading, batch size 1, chunk size
10, and 10 diffusion steps. Results use warmed-up CUDA Graph replay with two
current images and no history.

FP8 fast results:

| GPU | Default latency | FP8 fast latency | Approx. speedup |
| --- | ---: | ---: | ---: |
| NVIDIA GeForce RTX 4090 | 555.12 ms | 55.89 ms | 9.93x |

Measured with a DM05 LIBERO checkpoint, BF16 loading, batch size 1, chunk size
10, 10 diffusion steps, two current images, no history, and a 576-token prefix
bucket. Each backend used two runs of 20 warmup and 100 timed requests.
Calibration used 60 observations; validation used 20 observations from a
separate episode. Normalized action error against BF16 was 0.00148 MAE and
0.01225 maximum absolute error.

These are approximate model-inference speedups, excluding HTTP,
preprocessing, and first-request capture. History and overflow fallback
performance may differ.

### History-frame inference

History is opt-in and explicit: the server does not collect frames between
requests. The caller supplies an ordered `history_images` list with every
request. Frames must be ordered from oldest to newest.

Enable history on either backend by adding these CLI options to its startup
command:

```bash
--history-enabled --max-history-images 5
```

Both backends accept history frames. The default maximum is five images. The
fast backend has a fixed maximum of five and reserves five history slots in its
TensorRT vision engine. Therefore, a history-enabled engine for the standard
two-camera setup needs seven image slots. Give the fast history service a
dedicated vision engine path, separate from any prepared FP8 bundle:

```bash
CUDA_VISIBLE_DEVICES=0 python playground/benchmarks/libero/libero_dm05.py \
  --task inference \
  --backend fast \
  --model-name-or-path /path/to/dm05-checkpoint \
  --vision-trt-engine-path checkpoints/trt_engines/dm05-checkpoint-history.engine \
  --history-enabled \
  --max-history-images 5
```

For this LIBERO configuration, automatic engine building calculates the
seven-slot shape. To build the same engine separately, use `--num-images 7`:

```bash
CUDA_VISIBLE_DEVICES=0 python -m dexbotic.model.dm05.infer.fast.build_vision_trt \
  --checkpoint /path/to/dm05-checkpoint \
  --onnx-path checkpoints/trt_engines/dm05_vision_history.onnx \
  --engine-path checkpoints/trt_engines/dm05_vision_history.engine \
  --num-images 7
```

The RoboTwin2 entrypoint accepts the same two flags. Its fast backend uses three
current-view slots plus five fixed history slots, so use a separate eight-slot
TensorRT engine path when history is enabled. Automatic engine building selects
the eight-slot shape.

When automatic engine building is enabled, the fast backend calculates this
slot count automatically. A request containing history still uses TensorRT for
vision and the optimized DM05 kernels, but it runs prefix prefill and denoising
without a request-level CUDA Graph. Requests without history can continue to
use the lazily captured graph profiles. The history vision engine stays separate
from the checkpoint-local FP8 pair because their fixed image-slot counts differ.

The v1 API accepts history as an array of base64-encoded images. The legacy
`/process_frame` route accepts repeated multipart fields named
`history_images`:

```bash
curl -X POST \
  -F "text=Put the bowl on the plate" \
  -F "image=@/path/to/agentview.png" \
  -F "image=@/path/to/wrist.png" \
  -F "history_images=@/path/to/history-oldest.png" \
  -F "history_images=@/path/to/history-newest.png" \
  http://localhost:7891/process_frame
```

See [InferenceAPI.md](InferenceAPI.md) for the v1 JSON schema and `DexClient`
example.

## Training with Your Own Data

Write Dexdata JSONL, register it under `dexbotic/data/data_source`, then copy the
closest playground recipe. Use the generic LIBERO-style DM0.5 pipeline when
your data already stores the desired action trajectory. Use the RoboTwin2
adapter only when your contract also requires next-state absolute targets and
its state-conditioned prompt format.

Each frame needs images, `state`, and `prompt`. This example uses three views:

```python
dexdata_frame = {
    "images_1": {"type": "image", "url": frame["image_path_1"]},
    "images_2": {"type": "image", "url": frame["image_path_2"]},
    "images_3": {"type": "image", "url": frame["image_path_3"]},
    "state": frame["robot_state"],
    "prompt": frame["instruction"],
    "is_robot": True,
}
```

Register the dataset under `dexbotic/data/data_source/`:

```python
from dexbotic.data.data_source.register import register_dataset
import math

MY_CUSTOM_DATASET = {
    "my_robot_data": {
        "data_path_prefix": "",
        "annotations": "/path/to/your/custom_dataset/",
        "frequency": 1,
    },
}
meta_data = {
    "non_delta_mask": [6],
    "periodic_mask": [3, 4, 5],
    "periodic_range": 2 * math.pi,
}
register_dataset(MY_CUSTOM_DATASET, meta_data=meta_data, prefix="my_custom")
```

The registered name is `my_custom_my_robot_data`. Copy `libero_dm05.py` or
`libero_dm05_lora.py` and change these fields for the three-view example (keep
the two-view defaults when your data has two views):

```python
# DM05TrainerConfig
output_dir = [checkpoint dir]
num_train_steps = [steps]

# DM05DataConfig
dataset_name = "my_custom_my_robot_data"
num_images = 3
images_keys = ["images_1", "images_2", "images_3"]
valid_action_dim = 7

# DM05ModelConfig / DM05InferenceConfig
model_name_or_path = "./checkpoints/DM05"
action_dim = 7
camera_order = ["agentview", "wrist", "right_wrist"]

# DM05DataCollator (class attr; default is 2 views)
image_prompts = ("Head", "Left wrist", "Right wrist")
```

`num_images` must equal `len(DM05DataCollator.image_prompts)` (default
`("Head", "Left wrist")`). A mismatch raises.

```bash
torchrun --nproc_per_node=8 path/to/your_dm05_exp.py --task train
```

More Dexdata fields and multi-dataset `+` mixing:
[Data.md](Data.md#using-custom-data).

## Evaluation

Start the matching [inference service](#start-an-inference-service) for a
finished run or `checkpoint-*-hf`, then point
[dexbotic-benchmark](https://github.com/Dexmal/dexbotic-benchmark.git) at its
HTTP endpoint. Do not rely on the LIBERO full-SFT default path: without
`--model-name-or-path`, it serves the pretrained `./checkpoints/DM05` rather
than your fine-tuned run.

LIBERO and RoboTwin2 use the same evaluation flow: start the matching DM0.5
service on port `7891`, set the benchmark configuration's `base_url` to that
service, and run the corresponding `dexbotic-benchmark` evaluator. The model
repository only serves inference; environment rollout and metric collection
stay in `dexbotic-benchmark`.

### LIBERO

From a `dexbotic-benchmark` checkout, run the LIBERO evaluator against the
service:

```bash
cd dexbotic-benchmark
docker run --gpus all --network host -v $(pwd):/workspace \
  dexmal/dexbotic_benchmark \
  bash /workspace/scripts/env_sh/libero.sh \
  /workspace/evaluation/configs/libero/example_libero.yaml
```

To reproduce the official LIBERO numbers below, serve

### RoboTwin2

RoboTwin2 uses the same HTTP service boundary and the benchmark repository's
`robotwin2.sh` runner. Download the RoboTwin assets first, then mount the same
absolute asset directory at the locations expected by the image:

```bash
cd dexbotic-benchmark
export ROBOTWIN_ASSETS=/absolute/path/to/robotwin-assets
mkdir -p result_test

docker run --gpus all --network host \
  -v "$ROBOTWIN_ASSETS":"$ROBOTWIN_ASSETS" \
  -v "$ROBOTWIN_ASSETS":/app/assets \
  -v "$ROBOTWIN_ASSETS":/app/RoboTwin/assets \
  -v $(pwd)/evaluation:/app/evaluation \
  -v $(pwd)/scripts:/app/scripts \
  -v $(pwd)/result_test:/app/result_test \
  -e NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics \
  dexmal/dexbotic_benchmark \
  bash scripts/env_sh/robotwin2.sh \
  evaluation/configs/robotwin2/example_robotwin2.yaml
```

To reproduce the official RoboTwin2 numbers below, serve
[Dexmal/DM05-robotwin2](https://huggingface.co/Dexmal/DM05-robotwin2) as
described in [RoboTwin2 benchmark results](#robotwin2-results).

The example evaluates one task/configuration. For the complete result, run all
50 tasks separately with both `demo_clean` and `demo_randomized` (100
configurations total). Each configuration must point `base_url` at the DM0.5
service and use the serving contract above: the
`head_camera_rgb,left_camera_rgb,right_camera_rgb` views, a 14-D state,
`action_horizon: 50` (matching the training and inference `chunk_size=50`), and
`action_mode: absolute`. Results are written below
the configured `output_dir`; average the 50 per-task success rates for each
setting, then average the two setting scores for `Average`.

See the [dexbotic-benchmark README](https://github.com/Dexmal/dexbotic-benchmark)
for asset setup and Docker-free installation.
